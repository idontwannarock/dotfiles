## Context

使用者 2026-08-21 觀察到的缺口。既有規則寫的是「範圍只能是那一個 session」與
「你必須保留發問能力」，兩句都對，**而它們合起來仍然攔不住接班這一格**。

## Goals / Non-Goals

**Goals**：讓接班的協調者一定拿得到發問能力，且**不靠任何人記得**。

**Non-Goals**

- 不改「派線要關掉發問管道」這條規則本身（#32 的 A/B 實測支持它）。
- 不做機械守衛——見 D3。

## Decisions

### D1. 這是「套錯 session」，不是「範圍太寬」，所以要分開寫

| 失效形狀 | 出錯在哪 | 防法 |
|---|---|---|
| **範圍太寬** | 寫進設定檔，於是**所有** session 一起被關 | 「不要寫進設定檔」＋三層表 |
| **套錯 session**（本次） | 範圍正確（單一 session），**但那個 session 是你的接班人** | **交接時驗一次** |

合成一條會失去可操作性：第一種的動作是「不要那樣寫」，第二種的動作是「開完之後去驗」。

### D2. 防線放在「接手後第一件事」，不是放在「開接班人的時候」

兩個位置都可以放，但**只有後者讀得到**：

- 放在「開接班人時不要帶旗標」——**讀者是前任**，而前任可能已經 context 快滿、
  正在收尾、或根本不是它開的（使用者自己開的也算交接）。
- 放在「接手後第一件事」——**讀者是接班人本人**，而它正在讀這份 skill 的開頭，
  且它是唯一能實際驗證的人。

**兩個位置都寫，但承重的是後者。** 這是本 skill 自己那條規則的應用：
**一個只在某個人記得的時候才生效的防線，等於沒有防線。**

### D3. 沒有 CI 守衛，但有結構性的修法——兩道指令，不是「一道指令記得砍一段」

**初稿寫的是「這條只能靠接手時記得驗」，那個結論被 `coordinator` 推翻了，理由成立。**

CI 守衛確實不可能：**從外部查不到某個 pane 的 agent 手上有哪些 tool**，
`herdr agent list` 只給 name／pane／status，不給啟動參數。

**但結構性的修法可能**：

> **派線與開接班協調者用兩道不同的指令，不是同一道指令接班時砍掉一段。**
> **要人記得砍掉一段，遲早會有人忘記砍**——而它 exit 0、只警告不擋、接班人不會知道自己少了工具。

這是本 skill〈證據的資格〉那條「**與其多寫一段規則，不如問有什麼東西會在你做錯時擋住你**」
用在自己身上：**把兩件事寫成兩道指令，做錯就要多打一整行，而不是少刪一段。**

### D4. 現況是對的，而**沒有東西在維持它**——這才是要寫進去的那句

2026-08-21 實測（`ps -eo pid,args`，不經顯示層）：

| session | `--disallowedTools AskUserQuestion` |
|---|---|
| `coordinator` | **無**（正確） |
| `coordinate-v2`（起草本 change 的 session） | **無**（正確） |
| `port-sku-overrides`／`upload-verdict-optional`／`move-group-detail-path`（三條線） | **有**（正確） |
| `upgrade-recon` | **無**——**角色不明，未查證是不是被派出的線** |

**五個角色明確的全部正確。但它們正確不是因為有機制，是因為打指令的人剛好沒複製那一段。**

> **「分佈是對的」與「有東西在維持這個分佈」是兩件事，而後者不成立。**

這正是 skill 自己那句「**『沒有人會不高興』不是安全訊號，是『沒有東西在守這一格』的訊號**」
的實例——只是這次沒有人不高興的原因是**它剛好沒壞**。

### D5. 證據會隨著 pane 一起消失，所以防線必須在開線那一刻

`cmdline` 是唯一不經顯示層的硬證據，**而 process 結束它就沒了**。
`herdr agent list` 不給啟動參數；handoff 記「pane id 換了、名字不變」，不記指令。

> **一任協調者關掉前任的那一刻，前任是怎麼被開出來的就永久查不到了。**

⇒ **這個缺口不能靠事後稽核防。** 所以除了兩道指令，還要**開線時把 argv 落檔**
（開線紀錄與 handoff 放在一起），否則下一次要查「這一族有沒有再發生」時，
**唯一的證據已經不在了**。

### D6. 「`coordinator` 是名字不是 session」——我在提問時自己違反了

查證時我問「**你這個 session（第四任）**……」，而對方是**第八任**，
#41 那則的當事人是第六或第七任、pane 已被現任親手關掉。

> **答案會隨著今天第幾次換手而不同，而提問的人不會知道自己問的是哪一任。**

⇒ 這是〈證據的資格〉那條「**一個永遠有答案的讀取，答案可能屬於上一個時刻**」的**第四個載體**：
前三個是 pipeline 狀態、`git status`、idle pane 的畫面快照；
**這一個的受害者是「你問的那個人是誰」。** 提問要把時間或 pane 釘住，或接受答案只對當下有效。

### D4. 「驗」要驗什麼——列舉，不要寫成「確認工具正常」

**接手後第一件事的檢查清單**要能被逐條核對（#12：寫在散文裡與寫在清單裡效果不同）：

1. agent 清單裡 `coordinator` 這個名字指著你自己
2. **你手上有沒有 `AskUserQuestion`（或該 agent 的等價物）**——沒有就**立刻說**，
   不要等到需要用的時候
3. 廣播一次

第 2 項少了會怎樣：**你會在第一次需要升級到真人時才發現升級鏈斷了**，
而那時你手上多半已經有一條線停在那裡等你。

## Risks / Trade-offs

- **接班人若真的沒有那個工具，補不回來**（那是啟動旗標）→ 緩解：規則要寫明處置是
  **請使用者重開一個沒帶旗標的 session**，不是想辦法繞過；繞過就是回到「命名 fog 但照走預設值」。

## Open Questions

- ~~前三次換手實際上是怎麼開的？~~ **查不到，而且是永久查不到**（見 D5）——
  前任 process 已結束，cmdline 隨之消失。**這一格留白，不用推論補。**
- 現任 `coordinator` 的 cmdline 形狀「看起來就是派線那道指令砍掉旗標」，
  **但 cmdline 只記錄結果、不記錄誰按的鍵**，分不出「前任用改過的指令開的」與「使用者自己打的」。
  **當事人明確要求這一格留白，不要幫它填。**
- `upgrade-recon` 這個 session 沒有帶旗標，**角色未查證**。若它是被派出的線，那分佈就不是全對的。

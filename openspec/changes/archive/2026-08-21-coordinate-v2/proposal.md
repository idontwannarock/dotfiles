## Why

`coordinate` v1 凍結於 2026-08-21T01:10，之後兩天的實戰又累積了 39 條教訓，全部堆在 coordinator 維護的
`coordinate-v2-backlog.md` 裡——那份檔案不是 skill，沒有人會在協調時讀到它。教訓留在待納入清單，
等同於沒有被納入：下一個協調者仍會踩同一批坑，而且這批坑的共同特徵是**失效時是靜默的**
（工具回報成功、檢查是綠的、訊息照樣送達）。

## What Changes

- 新增〈證據的資格〉一節（主體）：把「拿來當證據的東西有沒有資格當證據」這一族收成四層檢查
  ——顯示欄位、驗證步驟、注入的差異、涵蓋範圍——並補上紅燈歸因與失敗計數兩條。
- 新增〈map 是線與線之間的那一格〉一節（主體）：wayfinder 四格之外的兩格（互斥的資源佔用、分歧的跨線量測），
  含寫入權分工表，以及「map 不要變成第三個正本」「handoff 目錄 ≠ map」。
- 擴充〈不要照單全收下游的結論〉：補上「後任 ← 前任」這個方向，以及否定斷言的通則
  （斷言之前先確認自己讀的是**能回答它的那個東西**）。
- 擴充〈整份覆寫之前先讀〉：補「該由誰說」是一格獨立的判斷；補條件寫的三層（先讀／錨點斷言／只碰自己那一列）。
- 擴充〈共寫檔〉：共寫資源不只是檔案——`git checkout` 本身也是，且一條線的 checkout 會靜默改變另一條線的部署行為。
- 擴充〈收尾〉：第五項（編號回收）之外加第六項「還有什麼只有你知道」，並補「順手解掉的小坑要有住址」。
- 擴充〈交付物不要留在會消失的地方〉：要在別人未來某個時刻生效的意見**寫成檔案**，訊息只適合當通知。
- 擴充〈認得複寫了別處的事實〉：補四處加強，並補比它高一階的形態——**測試站在錯的那一邊**。
- 擴充〈反模式〉：傳了規則卻沒傳前提；轉述第三方時混淆「它說了什麼」與「我因此想到什麼」；
  派下「統一處理」前沒問「現況為什麼不統一」。
- 附錄 A 擴充：輸入框判斷之前先做一次機械檢查（dim placeholder 不是 buffer 內容）；
  `agent prompt` 的訊息會經過一層 shell——三種靜默吃字的機制與完整修法。
- 新增〈誰有資格說這句話〉一節（主體）：把 backlog 分散在四處的 #1／#28／#39／#41 收成一族——
  失效機制同為「**一句話的署名跟它真正的來源對不上**」，而下游分辨不出來。含最極端的一格：
  協調者自己的選單回了一個使用者從未選過的答案，若照著走，下游會收到署名使用者、而使用者從未做過的裁決。
- 附錄 A 再擴充：傳訊管道分兩層（結構上免疫於吃字的那條，與仍然適用全部吃字機制的退路）；
  idle pane 的畫面讀取會回傳過期快照——**按鍵有效、讀取無效，而且沒有跡象**。
- 〈排程〉補一條：狀態條件不要寫成時序條件（兩者只在該狀態尚未成立時一致）。
- 〈收尾〉四訊號第②項改寫成可接受「不適用」：判準是**有沒有那個載體**，不是有沒有做那個動作。
- **不收**：#30（單獨關發問管道）已被 #32 的 A/B 實測推翻並隨 PR #107 落地；#7 已隨 PR #106 落地。

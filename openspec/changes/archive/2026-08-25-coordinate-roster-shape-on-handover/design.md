## Context

艦隊名冊（`fleet.md`）是 PR #118 建立、PR #119 修訂過的一份帳本：它記「這支艦隊**該有**哪些 session」，用來補掉 `herdr agent list` 結構上答不出的那一格——herdr 沒有 history 子命令、名字在 agent 退出時被清除，所以**已死的 session 與從未存在的 session 完全無法區分**。名冊與 herdr 的差集就是偵測器。

名冊之所以不算鏡子，理由寫在 D3（`2026-08-24-coordinate-fleet-scoped-addressing/design.md`）：它**只記「session 被換掉時不會變的東西」**。這條判準已在 `context/principles.md` 落為長青原則：「只記被替換時不會變的欄位——記了會變的欄位，鏡子的病就跟著回來。」

本輪處理的是那條判準的**兩處自我違反**，成因相同：名冊的 kind／旗標欄同時扛了兩個用途，而這兩個用途在「沒有交接」時重合、在「交接」時分岔。

| 用途 | 是什麼 | 交接時 |
|---|---|---|
| ① 重開處方 | 「這條線該長什麼樣」 | **不變**（若形狀受約束） |
| ② argv 證據 | 「這個 session 當初確實被這樣開出來」 | **過期**（新 process、新 argv） |

用途 ② 的立論在 body:789：`cmdline` 是唯一不經顯示層的證據，**process 一結束就沒了**。但同一份 body 在 :806 又承認它事後稽核不出東西——旗標欄位對「協調者」與「路人」給**同一個答案**，⇒「這一族只能在開線那一刻防，不能事後稽核」。所以用途 ② 的實際價值只剩事後鑑識，而它的代價是把一格會變的欄位放進帳本。

## Goals / Non-Goals

**Goals:**

- 讓〈交接時名冊一列都不用改〉這句話**真的成立**，而不是碰巧成立。
- 讓〈寫入只有派線與收尾兩個時機〉不再被 body 自己違反。
- 為「接班者形狀不對」這個失效指定一個**存在的、可執行的**責任方。

**Non-Goals:**

- **不**建立名冊的事後稽核機制。旗標的三態（線該有／協調者該沒有／路人無所謂）在 `ps` 上給同一個答案，稽核結構上答不出來；硬做只會得到一個測不準又會被學會忽略的 gate。
- **不**處理回報通道（大段訊息洗掉 context → 改「寫檔 ＋ 通知」）。那動的是不同條 requirement，且要重新設計「哪些訊息算 trigger、哪些算 payload」，另開一輪。
- **不**動 `map.md`、艦隊產物落點、資源池不得共用等其餘 requirement。

## Decisions

### D1：交接必須同形狀；換形狀不是交接，是「收線 ＋ 重新派線」

交接 ＝ 照名冊那一列的 kind ＋ 旗標原地重開，**啟動形狀不得變**。

**替代方案**：承認接班可換形狀，於是名冊需要第三個寫入時機。**否決**，三個理由：

1. **旗標由角色決定，不由 session 決定。** 線一定要帶關閉發問管道的旗標、協調者一定不能帶——這在 body〈第二種形狀〉已是不變量。交接改掉它不是一個要被記錄的新事實，是一個 bug。
2. **保住「協調者是名冊唯一寫入者」。** 開了第三時機就多一個寫入者（接班者自己）或多一道協調，而〈共寫檔〉在這支 skill 裡有三起實例，其中兩起靠對方回報才浮出來。
3. **與〈記指派的工作樹，不記觀測到的 cwd〉同一把尺。** 那一格已經在同一條軸上裁決過：名冊記的是**指派值**（不可變），不是觀測值。kind 與旗標套同一把尺，答案自己掉出來。

**換形狀怎麼走**：`kind` 真的要換（例如 claude 線交接給 codex）時，語意是「這條線收掉、協調者重新派一條」。重新派線就是**派線**，走既有寫入時機，不需要豁免。

<!-- evergreen-candidate -->
**判準**：一條規則若宣稱某欄位「不會變」，要先問它**憑什麼不會變**。答「碰巧沒人改它」就不是不變量，只是還沒被違反；答「有另一條規則禁止它變」才是。

### D2：規則課給前任，在讓出名字之前交代

前任 SHALL 在讓名前把自己的 kind ＋ 該不該帶旗標寫進交接文件，並明訂接班者 SHALL 以同形狀開出來。

**替代方案 A：課給接班者（上任後自驗）。** 單獨採用會失敗：旗標是**啟動參數，跑到一半補不回來**（body 明文），發現時已經來不及；而被關掉發問管道的線可能連報都報不出來。
**替代方案 B：協調者負責每一次重開。** 保證最強，但把協調者變成每次交接的必經路徑，且**協調者自己交接時這條規則無人可訴**。

採前任，理由是這是 skill 已有的形狀：「『你必須保留發問能力』只約束得到現任，現任讀它的時候接班人還不存在」——修法是把責任放在**還存在的那一方**。且前任是唯一知道自己 argv 的人（process 一結束就查不到）。

### D3：名冊只記「啟動形狀」，不記 `cmdline` 字串

那一格改記 **kind ＋ 角色 ＋ 該不該帶旗標**。

移除 `cmdline` 原文的三個理由：

1. 它是 per-process 事實，交接必變 → 正是 D3(#118) 判準要排除的那類欄位。
2. 它是那條「寫入只有兩個時機」的**唯一**反例；拔掉之後交接時名冊零寫入，規則第一次真的成立。
3. 它宣稱的用途（事後查得到怎麼被開出來）已被 body 自己在 :806 否定——**旗標欄位沒有資格區分「協調者」與「路人」**。

**代價**：失去事後鑑識用的 argv 原文。接受，因為留著它要付的是「帳本裡有一格鏡子」，而鏡子過期不會轉紅。

**替代方案：兩格分家**（形狀留名冊、`cmdline` 搬去追加式的艦隊 log）。否決：多一個檔、多一條規則，換來的是一份已知稽核不出東西的日誌。

### D4：接班者上任自檢，與協調者對稱——偵測並回報，不得自行代償

線在交接後上任 SHALL 查自己的 cmdline，比對名冊那一列的形狀；不符則具名回報協調者。

**這道與 D2 不冗餘**：兩者防的失效不同——D2 防「前任沒交代」（開線那一刻），D4 防「交代了但沒照做」（事後發現）。

**為什麼自檢可行而稽核不可行**（這兩件事看起來矛盾）：body:802 那句「`ps` 給的是『有沒有旗標』，你要判斷的是『該不該有』」講的是**第三方稽核**——稽核者不知道每個 session 的角色，所以分不出「沒帶旗標的協調者」與「沒帶旗標的路人」。但 **agent 自己知道自己的角色**。同一個 `ps` 讀數配上「我是誰」這個只有當事人有的資訊，就答得出「該不該有」。

**自我修正只在一半可行**：

| 半邊 | 交接後補得回來嗎 | 依據 |
|---|---|---|
| **旗標**（機械保障） | **補不回來** | 啟動參數；body 明文「跑到一半補不回來，不要自己想辦法繞過」 |
| **升級契約**（行為約束） | **補得回來** | prompt 層，協調者重發即可 |

2026-08-21 的 A/B 實測證明契約才是承重的那一半：**兩組都沒有發問工具**，唯一變數是有沒有契約；無契約組照樣挑了 V1.10 往下走。所以「線少了旗標」的正確補救不是繞過、也不是停擺，而是**確認契約在不在**——契約在，行為就對，只是失去機械保障這層備援。

**措辭必須是「偵測並回報」，不得是「偵測並自行代償」。** 後者正是本 skill 的頭號失敗模式：「命名了 fog 但照走預設值」。

<!-- evergreen-candidate -->
**判準**：「A 分不出 X 與 Y」這個結論綁的是**觀測者手上的資訊**，不是那個欄位本身。換一個手上多一項資訊的觀測者，同一個欄位可能就分得出來——所以「不可稽核」推不出「不可自檢」。

## Risks / Trade-offs

- **「同形狀」被違反時偵測器不會轉紅** → 名冊 ∩ herdr 差集在交接後兩邊都在，一律判「正常」。已知且結構性（見 Non-Goals）。緩解是 D2 ＋ D4 兩道人為義務，並在 spec 裡**寫明它不可事後稽核**，免得日後有人以為漏做了一個檢查而去補一個測不準的 gate。
- **D4 的自檢對「被關掉發問管道的線」可能報不出來** → 線的回報走 `herdr agent prompt` 文字通道，與發問選單是兩條路；文字通道不受該旗標影響。但若線連文字通道都壞了，這道自檢確實失效——那已是更上層的失效，不在本輪範圍。
- **失去 argv 原文** → 見 D3 代價。接受。
- **body 與 spec 兩處同步修改，漏改一處不會報錯** → 由 `sh tests/skill-name-map-axis.test.sh` 與 `openspec validate --all` 各把一面；兩者都不驗語意一致，所以 tasks 要把「spec 與 body 說法一致」列成獨立驗收項，由人讀。

## Migration Plan

無資料遷移。既有 `fleet.md` 若已寫入 `cmdline` 原文，該欄在下次派線時自然收斂為形狀；不需要回溯改寫（艦隊產物與艦隊同生同滅）。

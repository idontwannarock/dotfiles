## Context

三支守衛在 2026-08-25 的 review 中被雙方獨立打穿。缺陷全部同一族:
**守衛證明的命題比它宣稱的命題弱**,而兩者在綠燈上長得一模一樣。

## Goals / Non-Goals

**Goals:** 讓每支守衛實際證明的東西等於它檔頭宣稱的東西。

**Non-Goals:**

- 不抽 `tests/lib/`。cross-model 的反駁成立:獨立可執行的測試檔重複少量 `fail`/`finish` 是常規,
  抽共用庫會引入路徑耦合與一個新的共同失效點;而 `carrier-contract-sync` 守的是
  **跨契約的領域值**,不是測試骨架,兩者不同族。
- 不刪 `--> |` 分支。它是表格列的合法豁免形狀,由 self-check fixture 執行;
  「此刻沒有生產內容用到」不等於死碼。
- 不擴大禁令到「第N列」「第N種」。本輪只修守衛與它自己宣稱的落差。

## Decisions

### D1:豁免綁 token,不綁行

格式改為 `<!-- positional-ref: <token>: <理由> -->`。判定:
該行**每一個**命中的 token 都要在被豁免的 token 集合裡,否則轉紅。

這關掉的是:一行同時帶著為某個 token 寫的合法豁免、與另一個真違規。
舊實作只證明「這行有某個 token」就豁免整行——檔頭第 34-37 行卻明文宣稱這個 case 抓得到。
**宣稱與實作的落差比缺陷本身嚴重**:它讓下一個人停止再看。

配套三項:理由拒收純空白(`-n` 擋不住三個空格);行尾比對前先去尾隨空白
(markdown 的兩空格換行會讓合法豁免誤紅);標記之後若還有別的 HTML 註解,不算行尾標記。

### D2:同步守衛只探帶反引號的 token,並把載體納入 signature

`index(buf, "$")` 在兩三行的窗裡找一個單位元組,而 `$` 與 `!` 在 chezmoi 模板與一般散文裡到處都是。
實測:把 `` `!` `` 從規則移除、同時在下一句放一個驚嘆號 → signature 不變。
改探 `` `$` ``／`` `!` `` 這種**帶界定符**的形狀。

signature 另補**規則指名的來源與目的載體**。cross-model 的限定成立:現行 spec 只要求比
「門檻值與觸發字元集」,所以測試沒有違約——**是 spec 的範圍太窄**。所以 spec 與測試一起改。

### D3:每支守衛都要有一層斷言自己輸出的 fixture 檢查

`carrier-positional-reference` 的穩態是零匹配,所以整段回報路徑在健康 repo 上從不執行。
變異驗證:把 verdict 1 改算成豁免 → `ok: 0 ... exempt`、exit 0、self_check 全過。

範本檔(`path-format-flag-order.test.sh`)早就有這一層,而它的檔頭記著這一層是為了哪一次事故加的。
fixture 要斷言三件事:違規檔被點名、**豁免的那行不被點名**、建議文字有出現。

<!-- evergreen-candidate -->
**穩態為零的守衛,它的回報路徑是死碼。** 只斷言判別式不夠——判別式與訊息之間那一段
在健康 repo 上永遠不執行,而那正是它會壞掉又沒人發現的地方。要一層拿 fixture 跑整支腳本、
斷言它**說了什麼**的檢查。

### D4:xref 豁免以 `檔案 + 名字` 為鍵

因 `coordinate.md` 指向 handoff 標題而給的豁免,現在永久豁免整棵樹裡同名的每一處。
spec 的「逐條豁免」本來就指出現位置,不是名字。

### D5:CI 真的用 bash 跑

現行 `SEED_SH="$shell" sh "$t"`:harness 永遠是 `sh`,而兩支新測試根本不讀 `SEED_SH`。
job log 兩行綠是同一次執行跑兩遍。改為 `"$shell" "$t"` 並保留 `SEED_SH`,
既有的 subject 測試語意不變。

<!-- evergreen-candidate -->
**「跑兩個直譯器」要驗證的是 harness 真的換了直譯器,不是迴圈變數換了值。**
把 shell 名字只傳進環境變數而 harness 寫死,job log 會顯示兩行綠而實際只跑了一遍。

### D6:移除永不觸發的 `grep_status` 檢查

`$?` 拿到的是 `find` 的離開碼,GNU find 把 `-exec … +` 的任何非零都塌成 1,`-le 1` 永不觸發。
cross-model 正確指出 stderr 檢查仍接得住多數 grep 失敗,所以這不是靜默漏洞,
但**一段宣稱了保證而不提供保證的程式碼**要拿掉,不是留著加註解。

## Risks / Trade-offs

- **豁免格式改變會讓既有 6 個標記全部失效** → 同一輪一起改寫;測試轉紅就是驗收。
- **字元集放寬可能誤報**(如 `第3項` 出現在無關語境) → 母體是三棵受控的樹,誤報一次就加豁免,
  而豁免現在綁 token,不會順帶豁免整行。
- **fixture 模式是刻意的內部介面**,可被外部設定成空掃描 → cross-model 的判斷成立:
  刻意設它的人本來就可以乾脆不跑測試。不加防護,但在檔頭寫明它是內部介面。

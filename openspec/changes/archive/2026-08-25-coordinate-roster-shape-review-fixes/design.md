## Context

前一輪把名冊那一格從 `cmdline` 原文改成啟動形狀,修掉了兩處矛盾,但在六道 review 下露出七項 Critical。本輪的裁決不是重新設計,而是**修掉前一輪的實作瑕疵**,外加一項對前一輪裁決 D2 的推翻。

裁決來源分兩類,寫明是因為它們的證據等級不同:

| 來源 | 哪幾項 |
|---|---|
| 五個同家族透鏡 ＋ 我方自驗(grep／逐行比對) | E1、E4、E5、E6、E7 |
| 跨模型對辯(counterpart `codex`,只拿到 branch 名自行蒐證) | E2、E3 由它首倡;E3 的加重、E6 的收窄、以及**撤銷一條本方發現**由它完成 |

## Goals / Non-Goals

**Goals:**

- 補回被上一輪誤刪的職責(協調者那一列的創建),並讓「我的列不存在」變成一個顯性的 finding。
- 讓每一條新規則都有**投遞路徑**與**可執行的處置**,而不是只有措辭。
- 讓「不可事後稽核」這條禁令寫在它真正的成因上,使成因消失時它會失效而不是留著。

**Non-Goals:**

- **不**精簡上一輪重抄的約 35 行(使用者裁決:不收)。
- **不**新增任何稽核機制。收窄立論不等於改變結論。
- **不**處理回報通道改「寫檔 ＋ 通知」(仍在 backlog)。

## Decisions

### E1:協調者那一列在**開艦隊時**建立,寫入時機由二擴為三

寫入時機改為:**派線(增線的一列)／開艦隊(建協調者那一列)／收尾(刪一列)**。

**為什麼這不破壞「避開平行 append」的原設計**:那個設計要的不是「時機只有兩個」,是**寫入者只有一個**。開艦隊與派線都由協調者執行,寫入者仍然唯一。上一輪把手段(兩個時機)當成了目的。

**替代方案:名冊只收線,協調者不入列。** 否決——`:171` 的自檢要協調者比對形狀,而 `:864` 的三態表把「協調者」列為一個要被記住的角色值;更關鍵的是**協調者猝死會因此永遠不可偵測**,而線猝死可偵測,兩者不對稱沒有理由。

**連帶**:自檢要有「我的列不存在」這個分支,且該分支的處置是**回報這件事本身**,不是「沒事可查」。差集偵測器的第三列(名冊無而 herdr 有 = 不屬於本艦隊)否則會把協調者判成外人。

<!-- evergreen-candidate -->
**判準**:刪掉一段違規的文字之前,先問它**還扛著什麼別的職責**。一段文字同時是禁令的違反者與某個機制的唯一實作時,只針對違反那一面下刀會讓另一個機制靜默消失——而且不會有任何東西轉紅,因為那兩個職責從來沒有被分別命名過。

### E2:自檢的處置依角色分流

| 角色 | 不符時的處置 |
|---|---|
| 線 | 具名回報協調者(既有升級契約已含「並停下」) |
| **協調者** | **立刻對使用者說,並請使用者重開一個沒帶旗標的 session** |

**成因**:接班協調者的失效態正是升級鏈已斷,它沒有上級可報;而它是唯一該升級到真人的角色。上一輪把處置統一寫成「回報協調者」是迴歸——改動前是「沒有就**立刻說**」,且 `:877` 既有處置正是本表協調者那一列。

### E3(推翻上一輪的 D2):前任只寫**一句指路**,不搬資料

前任在交接文件寫的是:**「接班者 SHALL 以名冊那一列的形狀開出來」**——不複製 kind 與旗標的值。

**推翻的理由(由 cross-model 提出)**:上一輪給 D2 的立論是「前任是唯一知道自己 argv 的人」。這句在 D3 之後已經死了——名冊記的是**指派的形狀**,不是**觀測到的 argv**,而形狀由角色決定。沒有人需要前任的 argv。

**這一句話同時解掉三個問題**:`:1219` 禁止抄一份到 handoff 與 `:146` 要求寫進交接文件的矛盾消失;不需要優先權規則(名冊是唯一權威);`handoff` 那支 skill 也不必新增欄位(它的〈Principles〉本來就寫著 references over duplication)。

**D2 的新成因**:執行重開的那個人需要被告知**去讀哪一列**。這與 D4 仍然不冗餘,但理由換了:D2 是**預防**(讓重開這個動作一開始就對),D4 是**偵測**(重開已經發生之後才驗)。上一輪寫的「防不同失效」是對的直覺配錯的說法。

### E4:`:204` 改成命名兩個半邊,不用前者／後者

上一輪寫的「前任交代防『前任沒交代』」是套套邏輯,而下一句又把指涉調換,使得沒有一種讀法讓兩句同時為真。改成直接命名:**指路是預防、自檢是偵測**,並說明少了任一邊會怎樣。

### E5:「不可事後稽核」改寫在真正的成因上

**舊立論(本輪推翻)**:第三方不知道每個 session 的角色。**這在上一輪之後已經是假的**——上一輪正是把「角色 ＋ 該不該帶旗標」寫進名冊,而名冊就是那個「應該」欄。

**新立論**:阻礙是 **herdr 的名字與 process 之間沒有可靠的 join**。`agent list` 給 `cwd` 不給 pid、不給啟動參數,而 2026-08-21 那次實測裡角色是靠人知道的,同一次掃描還有四個 session 的角色無法從 argv 判定。

**結論不變,範圍收窄**:cross-model 明確指出「舊證明無效」**不等於**「稽核可行」——讀旗標仍然需要那個 join。所以 spec 仍然要求寫明不可事後稽核,但 SHALL 綁在 join 這個成因上,**join 出現時這條規則應當失效**,而不是留著一個沒有人記得為什麼的禁令。

<!-- evergreen-candidate -->
**判準**:「這件事做不到」的論證若在同一輪裡被自己的改動推翻,先分開問兩件事:**結論還成立嗎**、**理由還成立嗎**。兩者可以一真一假,而把還成立的結論配上已經失效的理由寫成永久禁令,是最難察覺的一種:結論看起來對,所以沒有人回頭查理由。

### E6:線側義務進派線訊息酬載,並同步 `dev-workflow`

自檢義務目前只寫在協調者的 skill 裡,而**沒有任何機制讓實作線載入 `coordinate`**。既有的投遞路徑是派線訊息(位址與升級契約走的就是這條),所以自檢義務要加進同一則,並同步進 `dev-workflow`〈coordinated mode〉的線側契約。

**引用更正**(cross-model 指出):`:994` 說的是線不讀你的 **handoff**,不是線不讀 skill。結論不變,但立論要改用「沒有機制讓線載入這份 skill」。

### E7:三處事實更正 ＋ 兩處 hedge

- `:140` 的「三起／兩起」統計本身為真,但屬 `:638`–`:658` 那一節,不屬〈共寫檔〉。改指正確標題。(cross-model 把本方原本「統計是假的」這條**降級**成導航瑕疵。)
- `context/principles.md` 那條長青原則:`ps` 三態表一致的是**「分不分得出」**欄,不是「該不該有旗標」欄(後者給三個不同答案)。正確的窄版主張只涵蓋兩個**未帶旗標**的態。
- **S2**:A/B 實測兩組都是**無工具**的,而「少了旗標」的線是**有**工具的——實測沒有涵蓋那個情境,推論要加 hedge。
- **S3**:「線一定要帶旗標」是角色層的應然,但只有 `claude` 有機械手段(其餘 kind「目前未知／多半沒有」)。自檢的「實際帶了沒有」在非 claude 線上無物可比,需要一條顯性退化規則,而不是讓它靜默通過。

### E8:更正前一輪的記錄

`tasks.md` task 5 的驗收寫成「剩下的每一處 `cmdline` 都必須是自檢用途」,而五處只有一處是自檢、其餘四處是**禁令**——驗收的形狀不符合它認證的主張。四處引用 `skill-name-map-axis.test.sh` 當關卡,而該測試對那個 diff **零涵蓋**(diff 動到的 `{{ }}` 行數為 0)。`design.md` 的 Migration Plan 說舊列「下次派線自然收斂」,但全檔沒有「就地改一列」這個操作。

歸檔的 artifacts 仍然更正,因為**歸檔是下一個人抄範本的地方**——一個沒有人能照字面滿足的綠燈,會訓練出對散文關卡的鬆散簽核。

## Risks / Trade-offs

- **寫入時機由二變三,「沒有平行 append」的宣稱要重新交代** → 緩解:把宣稱的依據從「時機只有兩個」改成「寫入者只有一個」,並在 spec 明白寫出後者才是承重的那一半。
- **E5 收窄之後,禁令綁在一個可能改變的工具限制上** → 這是刻意的:依〈限制要寫在它真正的成因那一層〉,綁在成因上正是為了讓它在成因消失時失效。要付的代價是有人得注意到 herdr 開始給 pid。
- **E6 動到第二支 skill(`dev-workflow`)** → 兩份文件的一致性沒有機器把關,列為獨立人工驗收項。
- **更正歸檔 artifacts 會讓 archive 與當時的 commit 不一致** → 接受:更正的是**事實錯誤**,不是重寫決策;且 git 歷史保留原貌。

## Migration Plan

既有 `fleet.md` 若仍是舊格式(含 `cmdline` 原文、或缺協調者那一列):**讀得懂即可,不要求回溯改寫**——舊列裡的 kind 與旗標當形狀讀;協調者那一列若缺,在下次盤點時補建。上一輪寫的「下次派線自然收斂」不成立,因為全檔沒有「就地改一列」這個操作。

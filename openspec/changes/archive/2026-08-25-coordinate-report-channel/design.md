## Context

`coordinate` 是協調者的 skill:自己不寫程式,產出是裁決、跨線事實、handoff。它與線之間的全部往來目前走單一管道 `herdr agent prompt <name> "<長文>"`。

**現行狀態有三處相關規則,彼此不一致:**

| 位置 | 現行說法 |
|---|---|
| 〈交付物不要留在會消失的地方〉末段 | 「訊息 vs 檔案」二選一,軸是**什麼時候生效**;檔案落 `~/.agent/handoffs/<repo-slug>/attachments/` |
| 〈跨線事實〉 | 「把合併後的結果**寫回每一條相關的線**」——動作是發訊息 |
| 附錄 A〈訊息內容會經過一層 shell〉 | 三個吃字機制,修法是 quoted heredoc / 挑 delimiter / **訊息寫進檔案再 `"$(cat file)"`** |

第三處那個「最保險」的修法已經指向檔案,但它把檔案當成**傳輸手段**(內容仍整段送進對方 context),不是當成**載體**。本 change 把它變成載體。

**約束:**

- **線不會載入本 skill。** spec 既有條文明寫此事。凡課給線的義務都得走派線訊息的酬載,並同步寫進 `dev-workflow` 線側契約。
- **body 是跨工具共用的。** `home/.chezmoitemplates/skills/*.md` 經 name-map 渲染到 Claude 與 Codex,新增工具專屬分支前要先讀 `tests/skill-name-map-axis.test.sh`。
- **`attachments/` 已無淘汰機制。** 實測 `mms_product_grouping_api` 該目錄 **117 個檔案**、5 天內堆出,混著 `__pycache__`、`.bak-*`、腳本、凍結版本。它綁 repo 不綁艦隊。

## Goals / Non-Goals

**Goals:**

- 讓協調訊息**可重讀**——原文活得比 context window 久,接手重驗時有正本可查
- 讓吃字整族在**結構上**消失於高風險訊息,而非繼續靠告誡
- 讓「這件事確實發生過」留下證據,把 `principles.md` 那條資料通道原則推廣到線與線之間
- 判準要**機械可驗**,不要「視情況判斷」

**Non-Goals:**

- **不追求省 context**。對方仍要把檔案讀進 context。省到的只有選擇性讀／晚點讀／不用讀三種情況,不足以當立論
- **不取消純訊息那一格**。取消它會讓「你可以合併了」也要建檔,成本明顯不對稱
- 不動 `fleet.md` 名冊欄位、`map.md` 格子、艦隊命名與定址
- 不建立回執機制(理由見 D4)

## Decisions

### D1:保留「什麼時候生效」這個軸,新增第三形態

判準軸維持**未來 / 現在**,新增一格「**兩者皆是**」:現在就要對方知道,且未來要能重讀。該格載體是**寫檔 ＋ 帶摘要的 prompt**,不是二選一。**跨線事實明文歸入這一格。**

| 這則內容 | 載體 |
|---|---|
| 只是現在要對方知道 | **訊息**(受 D5 升級規則約束) |
| 要在對方**未來**某個時刻生效 | **檔案**,訊息只說「有一份東西在那裡」 |
| **現在要知道,且未來要能重讀** | **檔案 ＋ 帶摘要的 prompt**——兩個都要 |

**替代方案與否決理由:**

- **換軸為「要不要立刻改變對方行為」**(資料 vs 指令)。否決:既有那格規則承重的軼事(一條線收線前交出的知識,讀者還沒開工)是**用時間軸推出來的**,換軸後那個軼事解釋不了新規則。而軼事是這份 skill 唯一的證據來源。
- **兩張表**(協調者交付物一張、線間訊息一張)。否決:同一個判準寫兩處,一處改了另一處不會知道——那正是 skill 自己那節〈認得「複寫了別處的事實」這一族〉。

⚠️ **兩軸不等價,這是本 change 的起點。**「現在要對方知道」**不等於**「要立刻改變對方行為」。跨線事實正坐在兩者的差集裡:現在就要知道,但它是資料。既有表把它判給訊息。

### D2:落點 `~/.agent/fleets/<repo-slug>/<fleet>/msgs/`,與艦隊同生同滅

**不新增判準**——沿用 skill 已立好的〈map:線與線之間的那一格〉那條:「**工作面會死,殘留的原則不會死,兩者不該同層**」。線間訊息按定義就是線與線之間的東西,與 map 同性質同落點。

**代價與配套:收線時要把該活過艦隊的搬出去**(handoff / memory / `attachments/`,走既有那三條路),〈收尾〉清單新增該項。

**替代方案與否決理由:**

- **全落 `attachments/`**。否決:117 檔案的傾倒場已證明它沒有淘汰機制,而線間訊息的量級遠大於交付物——落進去等於加速淹沒,而淹沒本身讓「可重讀」變成「找不到」。
- **全落 `fleets/` 且不搬**。否決:接手往往發生在**艦隊死後**,而「可重讀」的立論正是為接手服務的。不搬 = 該立論在最需要它的那一刻失效。

### D3:一則一檔,建檔不是覆寫

`~/.agent/fleets/<repo-slug>/<fleet>/msgs/<ts>-<from>-<to>-<topic>.md`。

**決定性理由不是整齊,是它讓〈整份覆寫之前先讀〉那一整族的失敗在結構上不存在**——不是被規則擋住,是**沒有那個動作**。檔名唯一,動作是建檔。該族三層守衛(先讀 / 條件寫 / 只碰自己那一列)在此佈局下全部無事可守。

**次要好處:** 通知的 prompt 只帶一個路徑,該路徑就是一則完整訊息,收訊方**沒有「讀到哪了」這個狀態要維護**。

**替代方案與否決理由:**

- **一線一檔 append**。否決:兩個洞。① **方向不對稱**——協調者→線的裁決落哪?擁有者是線的話協調者不能寫,於是要 `from-` ＋ `to-` 兩份,數量沒省到。② **「讀到哪了」是一個沒有地方記的狀態**,收訊方要自己在長檔案裡找哪一段是新的,而找錯是靜默的。
- **共用收件匣**。否決:收件匣按定義是多寫入者,而〈共寫檔〉那條的承重立論是「**沒有並行 append 的理由是寫入者只有一個**」。它答不出自己為何不重蹈。

### D4:不設回執;要確認對方接住了,去查它的產物

**回執答不了它要答的問題。** 回執只答「讀了」,而讀了不等於做了。兩條既有規則正面壓在這上面:〈證據的資格〉的「**一個永遠有答案的讀取,答案可能屬於上一個時刻**」,以及〈跨線事實〉的「**你是量的還是記的?**」——回執是自述,不是量測。

**採行 A ＋ B 併用:**

- **A(預設)**:要確認對方接住了 → 查產物(`git diff --stat`、檔案在不在、四訊號),不要問它
- **B(裁決類加掛)**:走 prompt 那一格的裁決,要求對方在**下一則本來就要發的**回報裡引用該訊息檔名。**搭在既有訊息上,不新增訊息,故不遞迴。** 它的價值不在「知道他讀了」,而在**引用錯檔名會露出來**——把一個靜默失敗換成一個看得見的不一致。

**替代方案(保留備查,不是否決得死死的):**

| 方案 | 為何這次不選 |
|---|---|
| 單 A | 少掉 B 那個「引用錯會露出來」的廉價守衛 |
| 單 B | 非裁決類訊息就完全沒有確認手段 |
| 顯式 `.ack` 檔 | 遞迴要靠「回執不需回執」這條**例外**擋住,而例外是規則裡最容易被下游推廣掉的東西 |

⚠️ **翻案條件(明訂):協調者實際遇到「分不出對方沒開檔／開了但判斷不需行動」,且該次的代價是實的。** 出現該情形時回頭看本表,不要重新發明。

### D5:一條升級規則,兩個觸發條件

> **純訊息含反引號、`$`、`!`、括號,或超過 5 行或 500 字元 → 自動升為第三形態。**

**寫成一條規則兩個條件,不是兩條規則**——兩者的處置完全相同(升到 D1 第三格),拆成兩條就是〈複寫了別處的事實〉。

**為何是守衛不是告誡:** skill 自己有〈取得嚴謹度的方法是守衛,不是告誡〉,而吃字這一族的紀錄是**同一天三起,其中一起是協調者在寫「怎麼避免被吃字」那則廣播時自己被吃了**。告誡在這一族上已有實測敗績。

**為何雙上限:** 只設行數會留漏洞——一行三千字的訊息照樣淹掉對方 session,而行數判準完全看不見它。

**為何 5 行:** 它剛好容得下第三形態的通知本身(一行說是什麼、一行路徑、一到兩行為什麼現在要看)。**門檻設得比通知本身大,通知就可能自己觸發升級,規則會咬自己的尾巴。**

**升級方向與判準自洽,這不是巧合:** 含技術符號或長內容的訊息,幾乎必然是資訊密度高、事後最需要重讀的那種——而那正是第三形態的定義。所以這條守衛**不是外掛的檢查,是判準自己推出來的**。

### D6:附錄 A 吃字那節縮範圍,不刪除

spec 現行明寫「退路那一節 **SHALL NOT 被刪除**」。本 change **沒有刪除它**,只是縮小它的適用範圍:它現在只管純訊息那一格(第三形態與純檔案都只帶路徑,那些字元不經 shell)。

⚠️ **要在 spec 裡把「縮範圍 ≠ 刪除」釘死**,否則下一輪覆核會把兩者讀成同一件事而判定違規,或反過來把縮範圍當成刪除的許可。

### D7:線側契約同步

`dev-workflow` 的 coordinated mode 一節新增本協定。**這是必然不是選擇**:沒有任何機制會讓實作線載入 `coordinate`。少了這一步,規則寫得出來、讀得到、就是**沒有人執行,而失敗是靜默的**。

<!-- evergreen-candidate -->
**「一則內容要走哪個載體,判準是它要在對方的哪個時刻生效;而含高密度技術符號或長度超標者,一律降級為『需要正本』的那一類。」** 這條的適用範圍超出 coordinate:凡是 agent 與 agent 之間、經過 shell、且內容可能含技術符號的通訊都適用。與 `principles.md` 既有「資料通道不得是螢幕輸出」同族,是它在「訊息 vs 檔案」這一軸上的細化。

## Risks / Trade-offs

| 風險 | 緩解 |
|---|---|
| **裁決帶齊「為什麼／前提／翻案條件」必然超過 5 行,被系統性推去寫檔;純 prompt 那格實際只剩「你可以合併了」這種一行話** | **接受,並視為正確結果而非副作用**——裁決正是最需要事後重讀的東西,也正是「接手要重驗繼承的結論」指的那種。要在 skill 裡明說這個後果,否則讀者會以為門檻訂錯了 |
| **協調者分不出「對方根本沒開那個檔」與「開了但判斷不需行動」** | 買單。兩者在 D4-A 底下長得一模一樣,而只有前者是壞的。翻案條件已明訂於 D4 |
| **收線時漏搬該活的,艦隊目錄被刪,沒有人會知道少了什麼——失敗靜默** | 掛進〈收尾〉那份清單(協調者自己驗的那半),與既有各項同一個強制點。⚠️ 這與 skill 裡「線收線前交出的知識」那個軼事是同一族,只是**這次執行刪除的是我們自己排的動作** |
| **`msgs/` 檔案數在實務上妨礙查找** | 與艦隊同生同滅,不跨輪累積——正是 D2 買到的東西。若仍然妨礙,翻案回 D3 的一線一檔 |
| **新增一層規則,而 skill 已經 1397 行** | 本 change **淨新增的規則只有一條**(D5 升級規則)。D1 是既有表加一格,D2/D3 是既有落點與既有寫檔紀律的套用,D4 是**不新增機制**的決定 |
| **body 改動可能打破 name-map 渲染** | `sh tests/skill-name-map-axis.test.sh` 為把關;新增工具專屬分支前先讀該測試(body 內已有註記) |

## Migration Plan

**無資料遷移。** 本 change 只改 skill 文字與 spec,不動任何既有檔案的格式或位置:

- `attachments/` 底下既有 117 個檔案**不動**——它們是協調者交付物,不是線間訊息,D2 沒有把它們納入
- 既有 `fleets/<repo-slug>/<fleet>/` 只多一個 `msgs/` 子目錄,`fleet.md` 與 `map.md` 不變
- 部署經 `chezmoi apply`,**限縮到本次子樹**並逐一 `chezmoi diff` 驗空(本機常比 repo 新,全量 apply 會退版)

**回滾:** revert 該 commit 即可,無殘留狀態。

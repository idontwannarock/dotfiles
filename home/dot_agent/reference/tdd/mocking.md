# Mock 邊界

## 原則

Mock 只放在**系統邊界**:網路、時鐘、檔案系統、第三方 API、
資料庫(依專案測試策略)。系統內部一律走真實介面。

## 為什麼

- 內部 mock 讓測試綁死實作結構 — 重構即紅。
- Mock 回傳值是你想像的行為,不是真的行為;內部 mock 疊多了,
  測試驗的是想像對想像。

## 訊號

某個內部模組「不 mock 就很難測」→ 這不是測試問題,是設計問題:
seam 太淺或職責糾纏。回報並考慮把它列入 design 討論,
不要用 mock 掩蓋。

## 邊界 mock 的品質

- Mock 的行為要忠於真實依賴的合約(錯誤形狀、edge cases)。
- 合約有疑慮時,補一個打真依賴的 smoke test 錨定。

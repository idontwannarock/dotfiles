# 好測試 / 壞測試

## 好測試

- 走真實介面的整合式測試:給輸入、驗可觀察的輸出行為。
- 讀起來像規格:測試名稱與內容說的是「系統應該做什麼」,
  不是「程式碼怎麼做」。
- 重構後仍存活:改實作不改行為時,測試不需要跟著改。
- 每個測試對應 spec 裡的一個 Scenario(WHEN/THEN)是理想形狀。

## 壞測試(反模式)

- **綁實作細節**:assert 內部呼叫次數、私有狀態、中間結構 —
  重構即紅,測的是「程式碼長這樣」而非「行為是對的」。
- **恆真測試**:靠構造必過(mock 回傳什麼就 assert 什麼)。
  刪掉實作邏輯還是綠的測試,沒有價值。
- **鏡像結構**:一個函式配一個測試檔、照實作結構排列 —
  測試套件應照行為組織,不是照檔案樹。

## 判斷法

問:「這個測試在實作全部重寫、行為不變的情況下,還會綠嗎?」
會 → 好測試。不會 → 重寫測試或重想 seam。
